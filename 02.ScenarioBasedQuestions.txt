You accidentally pushed code directly to the main branch. What will you do?

- Shared commit  -> git revert -> this will add a new commit that reverts my changes
- Not shared     -> git reset + force push (only with team approval)

Never rewrite history on shared branches.

------------------------------------------------------------
You accidentally committed secrets/API keys. What will you do?

- Revoke/rotate the credentials immediately.
- Remove them from Git history.
- Force-push the cleaned history.
- Notify the team.

Your PR contains many unnecessary commits. How will you clean it?

Suppose you worked on a feature and kept committing frequently. When you open a PR, reviewers see 5 commits, but only 2 are meaningful.
You can clean them using interactive rebase

I would use interactive rebase.

    git rebase -i HEAD~N --> Look back at last N commits

------------------------------------------------------------
A teammate force-pushed changes and your local branch history became inconsistent. What will you do?

    git fetch origin
    git reset --hard origin/main  --> Moves your current branch to exactly match origin/main, discarding any local changes.

------------------------------------------------------------
You accidentally deleted a branch. Can it be recovered?

- Yes. Git usually keeps references in reflog.

    git reflog

Find the commit hash and recreate the branch:

    git checkout -b branch-name <commit-hash>

------------------------------------------------------------
What precautions should be taken before using git rebase?

- Avoid rebasing public branches.
- Create a backup branch if needed.

------------------------------------------------------------
When should git revert be preferred over git reset?

- When commits have already been pushed to shared repositories

------------------------------------------------------------
What happens if you rebase a shared branch?

- Rebasing rewrites commit history and changes commit hashes. 
- Other team members may face conflicts and synchronization issues.

------------------------------------------------------------
How do you keep long-running feature branches updated?

- regularly synchronize them with main resolve
- avoid keeping branches open for very long periods.
