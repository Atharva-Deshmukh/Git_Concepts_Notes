===============================================================================
Branching & HEAD pointer
===============================================================================

Branch

- Independent line of development.
- Branch = Basically a Named pointer to latest commit, not a collection of commits

A --- B --- C
            ^
          main

main -> C

Git reconstructs history by following parent pointers.
main points to C -> C points to B -> B points to A

-------------------------------------------------------------------------------
HEAD

HEAD points to the currently checked-out branch.

HEAD -> main -> latest_commit

===============================================================================
Detached HEAD
===============================================================================

Occurs when checking out a commit instead of a branch.

git checkout <commit>

A --- B --- C
            ^
          HEAD

Normal:
HEAD -> main -> C

Detached:
HEAD -> C

-------------------------------------------------------------------------------
Commit in Detached HEAD

A --- B --- C --- D
            ^     ^
         main    HEAD

- HEAD moves to D
- No branch points to D
- D may become unreachable

-------------------------------------------------------------------------------
How to Return to Branch again -->  git switch main

A --- B --- C
            ^
          main
            ^
          HEAD

-------------------------------------------------------------------------------
Keep Detached HEAD Commit

A --- B --- C
      \
        D
        ^
      HEAD

===============================================================================
Undo Changes -- git reset vs git revert
===============================================================================

git reset
- Moves branch pointer backward
- Rewrites history
- Use for the Local commits only

A --- B --- C --- D

git reset --hard B

A --- B

--------------------------------------------------

git revert

- Creates a new commit that reverses the previous changes
- Safe for shared branches

A --- B --- C --- D --- E

E = Reverse of D

===============================================================================
Undo Last Commit
===============================================================================

git reset --soft HEAD~1   --> VS Code's Undo last commit
- Removes the commit
- But Keep changes STAGED

git reset HEAD~1
- Removes the commit
- Keep changes UNSTAGED

git reset --hard HEAD~1
- Removes the commit
- Discards the changes

===============================================================================
Merge vs Rebase
===============================================================================

MERGE
- Combines histories
- Creates Merge Commit
- Doesn't rewrite history

A---B---C
    \
     D---E

Merge

A---B---C------M
    \         /
     D---E---/

--------------------------------------------------

REBASE

- Replays commits
- Linear history
- Rewrites history

Before

A---B---C
    \
     D---E

After

A---B---C
          \
           D'---E'

Never rebase shared branches.

===============================================================================
Merge Types
===============================================================================

Fast Forward

A fast-forward merge happens when the target branch has no new commits since the feature branch was created.
Instead of creating a merge commit, Git simply moves the branch pointer forward.

A---B---C
         \
          D---E

Result

A---B---C---D---E

Command: 
  git merge feature

--------------------------------------------------------------------------------------
NOTE: git merge --no-ff feature

Command
  git checkout main
  git merge feature

Git decides automatically if a fast-forward merge is possible, Git performs it.

Before
A --- B --- C (main)
               \
                D --- E (feature)

Result

A --- B --- C --- D --- E (main)

✔ No merge commit is created.

Git simply moves the main pointer from C to E.

If fast-forward isn't possible:

A --- B --- C --- F (main)
               \
                D --- E (feature)

Then the same command -> git merge feature

creates

A --- B --- C --- F ------ M
               \          /
                D --- E --

because Git has no choice.


git merge --no-ff feature

This tells Git:

"Even if a fast-forward merge is possible, don't do it. Always create a merge commit."

Before
A --- B --- C (main)
               \
                D --- E (feature)

Command
  git checkout main
  git merge --no-ff feature

Result

A --- B --- C -------- M (main)
               \      /
                D --- E

Notice:

Merge commit M exists.
Git intentionally preserves the feature branch history.

Use of git merge --no-ff feature:
  Easier to revert an entire feature.
  Better release history.
--------------------------------------------------------------------------------------

Squash Merge

A squash merge combines all commits from a feature branch into a single commit before merging it into the target branch.

A---B---C
    \
     D---E---F

Result

A---B---C---G

G = Single Squashed Commit

Command:
  git merge --squash feature

===============================================================================
Git Tags
===============================================================================

Tag = Named reference to a commit -> Helps to remember the commit pushed during releases specifically
      Unlike a branch, a tag never moves.


git tag v1.0.0 D

A --- B --- C --- D(v1.0.0) --- E -- F -- G

main moves to G
Tag stays on D


MAJOR USECASE:

Imagine production crashes.

Current history:

  A --- B --- C(v1.0.0) --- D --- E --- F(v2.0.0)

You can immediately go back to the exact code released as v1.0.0:

  git checkout v1.0.0

No need to remember the commit hash.


Create a tag on current commit
  git tag v1.0.0

Create a tag on a specific commit
  git tag v1.0.0 <commit-hash>

List tags
  git tag

Checkout a tag
  git checkout v1.0.0

Push a tag
  git push origin v1.0.0

Push all tags
  git push --tags
