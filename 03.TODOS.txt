BRANCHING STRATEGY AT CURRENT ORGANISATION
/*
Our team follows an environment-based branching and deployment flow.

Developers usually work on feature branches and merge changes into 
the development branch after review and validation.

The deployment pipeline promotes builds across multiple environments:

dev -> feature-int -> prod-int -> prod

- dev:
  Initial development and basic validation.

  validated together.

- prod-int:
  Pre-production/staging environment used for regression, 
  stability, and release validation.

- prod:
  Production release environment.

Automation suites are executed across these environments through 
GitLab CI pipelines to ensure stability before production release.
*/

1. You committed directly to main/master branch accidentally. What will you do?

Expected discussion:

avoid force push
revert commit if already pushed
create PR workflow
notify team if needed

Good answer:

“If already pushed, I would use git revert instead of reset to safely undo changes without rewriting shared history.”

2. You pushed a broken automation script and CI started failing. How will you handle it?

Expected points:

identify failing commit
revert or hotfix
validate locally
rerun pipeline
communicate with team
3. You and another engineer modified the same file. What happens during merge?

Expected:

merge conflict
manual resolution
verify changes
commit resolved file
4. Your feature branch is outdated by several commits. How will you update it?

Expected:

git fetch
merge or rebase main branch

Bonus:
Explain when to prefer merge vs rebase.

5. You want to temporarily switch tasks but your current code is incomplete.

Expected:

git stash
git stash pop
6. You accidentally committed secrets/API keys. What will you do?

Expected:

revoke secret immediately
rotate credentials
remove from repo history if necessary
add to .gitignore

Interviewers mainly care about awareness.

7. A teammate force-pushed and your branch history became messy. What will you do?

Expected:

fetch latest changes
inspect history
rebase carefully
coordinate with teammate
8. Your PR has 25 messy commits. Reviewer asks to clean history.

Expected:

interactive rebase
squash commits
meaningful commit messages
9. CI pipeline passes locally but fails after pushing. What steps will you take?

VERY common for SDET.

Expected:

check logs
env differences
dependency mismatch
flaky tests
timing issues
secrets/configuration
10. How do you manage multiple automation engineers working on same framework?

Expected:

feature branches
small PRs
regular sync with main
code reviews
modular framework design
11. You need only one commit from another branch. What will you use?

Expected:

git cherry-pick
12. You accidentally deleted a local branch. How can you recover it?

Expected:

git reflog
recover commit hash
recreate branch

High-level explanation enough.

13. A flaky test is breaking pipelines repeatedly. How do you handle it in Git workflow?

Excellent SDET-specific question.

Expected:

quarantine/tag flaky tests
isolate changes
avoid blocking releases unnecessarily
root cause analysis
14. Your branch has merge conflicts during release week. What precautions will you take?

Expected:

avoid risky rebases
communicate with team
test thoroughly after merge
smaller commits
15. You need to rollback a production automation change quickly.

Expected:

revert commit
rerun validation pipeline
deploy stable version
16. A PR contains unrelated changes. What should be done?

Expected:

split commits
cherry-pick clean commits
create smaller focused PRs
17. You pulled latest changes and suddenly many tests started failing.

Expected:

inspect changed modules
compare diffs
dependency/config changes
rerun impacted suites
18. Your local branch diverged from remote branch.

Expected:

fetch latest
inspect commits
merge/rebase appropriately
19. How do you ensure stable Git workflow in automation frameworks?

Excellent SDET-2 question.

Expected:

branch protection
mandatory PR review
CI validation
linting/hooks
modular code structure
20. Describe a real merge conflict you resolved.

VERY commonly asked behavioral question.

You should prepare a real story from:

Cypress → Playwright migration
shared utility changes
locator conflicts
config updates
