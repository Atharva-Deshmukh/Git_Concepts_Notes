Git: Distributed version control system used to track changes in code

------------------------------------------------------------------------------------
 Git Vs GitHub/GitLab?

              Git -->  version control system used locally.
GitHub and GitLab -->  are cloud-based platforms that host Git repositories.

------------------------------------------------------------------------------------
Version control system: A tool that manages multiple versions of code, tracks changes, allowing teams to collaborate.

------------------------------------------------------------------------------------
(CVCS) and (DVCS)

Centralized version control system (CVCS):
- there is a single central server that stores all versions of the code, and users  depend on that server. 
- They need to connect to that server to get latest changes
- Online work is there, no offline scope

  Ex:
    - SVN (Apache Subversion)
    - Perforce
      Generally old legacy systems used these.

Distributed version control system (DVCS): 
- every user has a complete local copy of the repository and its history, 
- enables offline work and better collaboration.

  Ex: Git

What is `.gitignore`?

A special file used in Git to specify which files and folders should be ignored (not tracked) by Git.

Why use it?
- Avoids uploading sensitive files such as passwords, API keys, or environment variables.

Example:

# Ignore node_modules folder
node_modules/

# Ignore environment file
.env

# Ignore build output
dist/
build/

------------------------------------------------------------------------------------
Tracked Vs Untracked files?

Tracked Files:
- Files that Git is already monitoring (detects changes).

Untracked Files:
- Files that exist in the working directory but are not being monitored by Git.

How do you undo the last commit?

                                    git reset --soft HEAD~1

- Removes the commit but Keeps the changes staged
- Used when we have to edit the last commit message or changes

                                      git reset HEAD~1

- Removes the commit and unstages those changes
- Changes can be seen using git status

                                    git reset --hard HEAD~1

- Removes the commit and discard all changes
- HEAD is moved to previous commit

------------------------------------------------------------------------------------
How do you undo uncommitted changes?

Undo changes in a specific file --> git restore filename
Undo changes in all tracked files --> git restore .
git restore app.js --> This restores app.js to its last committed state.

What is branching in Git?

- Creating an independent line of development inside a repository. 
- A branch is not actually a collection of commits.
- A branch is just a named pointer (reference) to one commit — usually the latest commit in a line of development.

  A --- B --- C
                ^
              main

            main is just a label storing: main = commit C
            Nothing more.

            Commit C itself stores a pointer to B.
            Commit B stores a pointer to A.

            So Git walks backward through history.

------------------------------------------------------------------------------------
What is HEAD in Git?

- HEAD is a pointer/reference to the currently checked-out commit.
- Usually, HEAD points to a branch (like `main` or `feature/login`), and that branch points to the latest commit.
- When you create a new commit, the branch moves forward, and HEAD moves with it.

Example:
    HEAD -> main -> commit abc123

------------------------------------------------------------------------------------

What is a detached HEAD state?

  When we checkout a commit directly: git checkout <commit-hash>
  HEAD no longer points to a branch.

  Instead: HEAD -> C directly.

  So now:

    A --- B --- C
                ^
               HEAD

  No branch name is involved.

                                      Why new commits become “dangling”?

  If you commit now:

    A --- B --- C --- D
                        ^
                      HEAD

  Git creates commit D, and HEAD moves to it.
  But no branch points to D.

  Normally you'd have: main -> D

  But in detached HEAD: HEAD -> D only temporarily.


SOLUTION: If you detached HEAD by checking out an older commit, you can move back to the latest commit simply by
checking out a branch again.

Example situation:

                                A --- B --- C   main
                                      ^
                                    HEAD

You checked out commit B, so HEAD is detached.

To return to the latest commit on main (C):
    git switch main
or older syntax:
    git checkout main

Now:

                                  A --- B --- C
                                                ^
                                              main
                                                ^
                                              HEAD

HEAD is attached again.

If you made commits while detached:

                                  A --- B --- C
                                        \
                                          D
                                          ^
                                        HEAD

Then switching to main leaves D unreferenced.

To keep it: git switch -c new-branch 
before leaving detached HEAD.


Quick way to return to previous branch: git switch -
This switches back to the branch you were on before.

How do you delete a branch locally and remotely?

               Delete locally --> git branch -d branch_name
  Force delete a local branch --> git branch -D branch_name
       Delete a remote branch --> git push origin --delete branch_name

       -d -> allows deletion if the branch has already been fully merged
             means, all commits of <source_branch> must be at the <target_branch>

            ex: 

              git checkout main
              git merge feature-login

              After this merge, Git considers feature-login fully merged, so this works: git branch -d feature-login

      -D -> Deletes the branch even if it contains unmerged changes.

What happens internally during `git commit`?

  Git performs these steps:

  1. Reads the staged files added using git add .
  2. Creates blob (Binaly Large Objects) objects inside the `.git` directory
  3. Creates a commit object with message and timestamp
  4. Generates a unique commit hash (SHA)
  5. HEAD moves to the latest commit

What is the difference between `git checkout` and `git switch`?

                                `git checkout`

- Older command with multiple purposes:
  - Switch branches
  - Checkout commits/tags
- Can be confusing because it does many unrelated tasks.

Examples:
    git checkout main
    git checkout abc123
    git checkout -- file.txt

                                `git switch`

- Used only for switching branches.

Key Difference:
- `git checkout` = multi-purpose command
- `git switch` = branch switching only

Switch to an existing branch       --> git switch <branch-name>
Create and switch to a new branch  --> git switch -c <new-branch-name>
Toggle back to the previous branch --> git switch -


Modern recommendation:
- Use `git switch` for changing branches.
- Use `git restore` for restoring files.
- Use `git checkout` mainly for older workflows or compatibility.

What is `git log` used for?

used to view the commit history of a Git repository. It displays commit IDs, authors, dates, and commit messages.

Examples:
git log               → Shows detailed commit history.
git log --oneline     → Shows a compact one-line history.
git log --graph --all → Displays commit history in graph form.
